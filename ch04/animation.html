C4-1 Race Condition Interleaving

두 Thread가 counter++ (Load → Add → Store)를 실행합니다. 명령이 섞이는 순서에 따라 공유 Memory의 값이 어떻게 달라지는지 단계별로 확인합니다.

C4-2 Compare-And-Swap Simulator

"내가 본 값 그대로면 교체, 아니면 실패". CAS가 성공하는 경우, 실패하고 재시도하는 경우, 그리고 값만 비교하기 때문에 생기는 ABA 문제를 확인합니다.

C4-3 Store Buffer와 Memory Ordering

두 CPU가 각각 "쓰고 나서 상대 변수를 읽습니다". 쓰기가 Store Buffer에 머무는 동안 무슨 일이 일어나는지, Memory Barrier가 무엇을 바꾸는지 확인합니다.

C4-4 Futex: Fast Path와 Slow Path

mutex의 상태는 User Space의 정수 하나에 있습니다. 경쟁이 없으면 Atomic 명령으로 끝나고, 경쟁할 때만 futex System Call로 Kernel에 들어가 잠듭니다.

C4-5 Cache Line과 False Sharing

두 Core가 서로 다른 변수 a, b를 증가시킵니다. 두 변수가 같은 64Byte Cache Line에 있을 때와 떨어져 있을 때, Line의 상태(MESI)와 Core 간 통신이 어떻게 달라지는지 비교합니다.
