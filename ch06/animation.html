C6-1 Readiness vs Completion

epoll은 "읽을 수 있게 되면 알려 주는" Readiness 모델입니다. Pipe에는 잘 맞지만 Disk File에는 맞지 않습니다. I/O를 맡기고 "끝났다"를 통지받는 Completion 모델과 비교합니다.

C6-2 io_uring Architecture

요청 하나가 Setup부터 완료까지 지나는 과정입니다. 각 단계에서 User ↔ Kernel 경계를 넘는지(System Call인지, 그냥 Memory 접근인지)에 주목하세요.

C6-3 SQ / CQ Ring Buffer

SQ 4칸, CQ 8칸의 작은 io_uring입니다. head와 tail이 어떻게 움직이고 각 칸이 어떤 상태를 거치는지 확인합니다. 아래의 "직접 해 보기"에서 Create SQE, Submit, Kernel Process, Complete, Read CQE 버튼으로 Ring을 직접 움직여 보세요.

C6-4 Batch와 System Call

같은 8개의 읽기를 세 가지 방식으로 수행합니다. User ↔ Kernel 경계를 몇 번 넘는지, 그리고 줄어들지 않는 비용이 무엇인지 확인하세요.

C6-5 I/O Model 비교

같은 일(Data 읽기)을 다섯 가지 모델로 수행합니다. Application Thread가 그동안 무엇을 하는지, 누가 I/O를 수행하는지, System Call이 몇 번인지 비교하세요. 어느 것이 "가장 빠른가"가 아니라 풀려는 문제가 무엇인가를 봅니다.
