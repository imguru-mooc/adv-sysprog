1-2. 이 과정이 답하려는 질문

기존 과정을 마쳤다면 아래 코드는 어렵지 않습니다.

int fd = open("data.log", O_WRONLY | O_APPEND);
write(fd, buf, len);      /* return 값은 len */
close(fd);

그런데 다음 질문은 어떨까요. 넘어가기 전에 각 질문에 대한 자신의 답을 종이나 메모장에 한 줄씩 적어 보세요. 과정이 끝난 뒤 다시 보면 무엇이 달라졌는지 알 수 있습니다.

  1. write()가 len을 return했습니다. 바로 이 순간 전원이 꺼지면 Data는 Disk에 남아 있을까요?
  2. read()를 호출하면 항상 Disk를 읽을까요?
  3. pthread_mutex_lock()은 호출할 때마다 Kernel에 들어갈까요?
  4. malloc(1GB) 직후 top에서 Memory 사용량이 거의 늘지 않습니다. 왜일까요?
  5. 프로그램이 느립니다. 무엇부터 조사해야 할까요?

이 질문들은 API 문서(man page)만 읽어서는 답하기 어렵습니다. 답은 System Call 경계 아래, Kernel 안에 있습니다.

질문 답을 찾게 되는 곳
1 Chapter 3, L15 Writeback, fsync 그리고 데이터 영속성
2 Chapter 3, L13 Page Cache
3 Chapter 4, L19 Futex 내부 구조
4 Chapter 2, L09 Page Fault 내부 동작
5 Chapter 7 전체

1-3. 기존 과정과 무엇이 다른가

기존 과정 이번 과정
질문 어떻게 사용하는가 왜 이렇게 동작하는가
범위 API와 사용 Pattern System Call 아래 Kernel 동작, CPU와 Memory
확인 방법 실행 결과 strace, /proc, perf, ftrace, bpftrace로 직접 관찰
execve 호출하면 프로그램이 교체된다 ELF가 어떻게 Mapping되고 main()까지 가는가
mutex lock / unlock 사용법 언제 futex로 Kernel에 진입하는가
read / write fd와 buffer VFS, Page Cache, Writeback, fsync

가장 큰 차이는 확인 방법입니다. 설명을 듣고 끝내지 않고, 설명한 내용이 사실인지 도구로 직접 확인합니다.

1-5. 이 과정에서 다루지 않는 것

Network Programming 전체를 다루지 않습니다: socket, bind, listen, accept, TCP/UDP, HTTP, Network Server. 이 내용은 별도 과정 Linux Network System Programming에서 다룹니다.

select / poll / epoll은 다룹니다. 다만 Network API가 아니라 여러 File Descriptor를 한꺼번에 기다리는 범용 메커니즘으로 다루며, 실습에는 socket 대신 아래 FD를 사용합니다.

pipe   FIFO   eventfd   timerfd   signalfd   inotify

Processor는 반드시 2개 이상으로 설정하세요. VirtualBox 기본값은 1개인 경우가 많습니다. CPU가 1개이면 두 Thread가 실제로 동시에 실행되지 않아 Chapter 4의 Race Condition, Memory Ordering, False Sharing 실습이 재현되지 않습니다.

📌 NOTE
기존 과정에서 Bridge나 Host-only 방식으로 접속했다면 그 방식을 그대로 써도 됩니다. 이 문서는 설정이 가장 단순한 NAT + Port Forwarding 기준으로 설명합니다.

Hardware Counter WARN은 정상입니다

perf가 세는 Event는 두 종류입니다.

종류 누가 세는가 예 VirtualBox
Software Event Kernel page-faults, context-switches, cpu-clock 사용 가능
Hardware Event CPU 안의 PMU cycles, cache-misses, dTLB-load-misses 대부분 <not supported>

VirtualBox는 CPU의 PMU를 VM에 보여 주지 않습니다. 그래서 이 과정은 다음과 같이 진행합니다.

  • 모든 기본 실습은 Software Event와 실행 시간 측정으로 구성되어 있어 VirtualBox에서 그대로 따라 할 수 있습니다.
  • cache-misses, dTLB-load-misses가 필요한 장면(L08, L20, L33)은 Native Linux에서 측정한 결과를 문서와 영상에 함께 싣습니다.
  • 직접 해 보고 싶다면 PC에 Ubuntu 26.04를 직접 설치하거나 PMU를 노출하는 Hypervisor(KVM 등)를 사용합니다. 필수는 아닙니다.

2-8. 도구 동작 확인

hello_trace는 세 가지 일만 합니다: write 한 번, malloc 한 번, Memory 256 Page에 쓰기. 같은 프로그램을 네 가지 도구로 봅니다.

먼저 Source를 읽어 봅니다: hello_trace.c

8-1. Build와 실행

make
./hello_trace

hello, kernel
pid=2314 page=4096 touched=256 pages

8-2. strace: System Call을 본다

strace -e trace=write ./hello_trace

write(1, "hello, kernel\n", 14)         = 14
hello, kernel
write(1, "pid=2320 page=4096 touched=256 p"..., 37) = 37
pid=2320 page=4096 touched=256 pages
+++ exited with 0 +++

write가 두 번 보입니다. 첫 번째는 Source의 write()이고, 두 번째는 printf()가 내부에서 호출한 것입니다.

8-3. ltrace: Library 함수 호출을 본다

ltrace -e malloc+memset+free ./hello_trace

hello_trace->malloc(1048576)                     = 0x7f3a1c2ff010
hello_trace->memset(0x7f3a1c2ff010, '\001', 1048576) = 0x7f3a1c2ff010
hello_trace->free(0x7f3a1c2ff010)                = <void>

malloc과 memset은 System Call이 아니라 Library 함수이므로 strace에는 보이지 않고 ltrace에만 보입니다.

8-4. perf stat: Kernel Event를 센다

perf stat -e page-faults,context-switches ./hello_trace

 Performance counter stats for './hello_trace':

               318      page-faults
                 0      context-switches

page-faults가 256보다 큰 값이면 정상입니다. memset이 256개의 Page를 처음 건드리는 순간마다 Page Fault가 발생하기 때문입니다. 나머지는 프로그램을 Memory에 올리는 과정에서 발생합니다. (Chapter 2에서 자세히 다룹니다.)

Permission 오류가 나오면 sudo perf stat ...으로 실행합니다.

8-5. bpftrace: Kernel 안에서 본다

sudo bpftrace -e 'tracepoint:syscalls:sys_enter_write /comm == "hello_trace"/ { printf("write fd=%d len=%d\n", args->fd, args->count); }' -c ./hello_trace

Attaching 1 probe...
hello, kernel
pid=2331 page=4096 touched=256 pages
write fd=1 len=14
write fd=1 len=37

strace와 같은 write 두 번이 보이지만 방식이 다릅니다. strace는 Process를 멈춰 가며 밖에서 지켜보고, bpftrace는 Kernel 안에 작은 프로그램을 넣어 기록합니다. 차이는 Chapter 7에서 다룹니다.

📌 NOTE
지금은 출력이 나오는지만 확인하면 됩니다. 같은 프로그램인데 도구마다 보이는 층이 다르다는 점만 기억해 두세요.

2-9. Snapshot 만들기

이 과정에는 root 권한으로 System 설정을 바꾸는 실습이 많습니다: drop_caches, ftrace, bpftrace, cgroup, namespace, pagemap. 지금 상태를 저장해 두면 언제든 되돌릴 수 있습니다.

  1. VM에서 sudo poweroff로 종료합니다.
  2. VirtualBox에서 VM을 선택하고 Snapshot > 찍기(Take) 를 누릅니다.
  3. 이름을 tools-installed로 저장합니다.

✏️ 괄호 넣기 0.2-2
